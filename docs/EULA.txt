The current desktop application reads CBMS JSON data supplied by the authorized operator. It does not bundle local CBMS raw datasets and does not contain or distribute PSA RSA decryption keys.

6. EXPORT SECURITY — AES-256 PROTECTION
The Software’s file-export functions are designed to protect exported data using password-protected AES-256 encrypted containers. CSV, XLSX, PDF, and DOCX exports are wrapped in password-protected AES-256 ZIP archives. Protected HTML report exports use AES-256-GCM encryption with a derived key. The Software generates export passwords and records export details locally for authorized retrieval. The export password must be kept separate from the exported file.

Every protected file export generated by CBMS Insights through its protected export workflows is wrapped using AES-256-based encryption as described above. The protection applies to the exported archive/container or protected HTML file created by the system; it does not convert an externally copied, manually recreated, or printed document into an encrypted artifact.

The AES-256 protection applies to the Software’s protected file-export workflows. It does not mean that a physical printout, a screen display, or an unprotected copy intentionally created outside the Software is encrypted. The LGU remains responsible for secure handling of exported files and passwords.

7. LOCAL DATA STORAGE
Imported CBMS data is processed locally on the authorized workstation. The application may cache normalized runtime data in the workstation’s local application storage so that imported datasets remain available after a restart. This local cache is not presented as a substitute for full-disk encryption or Windows account security. Use appropriate OS-level security, access controls, and disk encryption where required.

8. SECURITY CONTROLS
When configured, the Software protects startup access with a six-digit PIN. Three consecutive incorrect attempts cause a persistent ten-hour lockout. PIN verification and lockout enforcement run in the Electron main process. The stored PIN verifier uses a memory-hard scrypt derivation, while the authentication record is protected with authenticated AES-256-GCM and an OS-protected application key where available.
